# Contributing

Changes should be focused, testable, and free of private deployment data. Describe the problem, the approach, and the tests actually run. For behavior or security changes, retain meaningful positive and negative tests.

Use [the offline quick start](docs/quickstart.md) to set up Python and identify the full CI test selection. Firmware changes should also follow the pinned-Kai and host-test instructions. Do not commit real credentials, private configuration, databases, or logs. Use synthetic examples and reserved example hosts or addresses.

Report security vulnerabilities privately rather than filing public issues; see [SECURITY.md](SECURITY.md). By submitting a change, ensure you have the rights to contribute it under the project license and preserve third-party attribution.
